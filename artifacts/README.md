# Artifact sources live here, in git — and so does the built page

A published Artifact lives on someone else's server, under an org you may leave. The page can become unreachable without anything local changing: an account switch, an org's External-sharing toggle, a plan change. So **the source that rebuilds the page AND the built HTML are the durable copy, and both belong in version control** — not in `tmp/`, not in `$TMPDIR`, not in a worktree that gets deleted.

This directory is the standard home for both. `ARTIFACTS.md` in the repo root maps each published URL to what the page established; its **Source** column points here.

## Why this exists

`ARTIFACTS.md` records that eight of its rows are retro-attributed, matched to this repo by subject matter, "because no built HTML was kept for any of them". Those pages cannot be rebuilt, corrected or re-published — only read, and only while the link resolves. The convention below is what stops that recurring.

The failure is easy to walk into. A page built in `tmp/` publishes perfectly and looks finished; the loss is invisible until the worktree is removed or the org changes, which is long after anyone would connect the two.

## Layout

```
artifacts/
  <slug>/                 slug matches the artifact's title, kebab-case
    meta.yml              url, title, org, status, dates, summary, author_model — and the ARTIFACTS.md row
    <source>              what rebuilds the page: .md, .html, or a build script
    <slug>.html           the built page, committed beside the source
    build/                gitignored — intermediates and scratch only
  index-rows/             one file per row whose page has no directory (README.md there)
```

**Commit the source and the built HTML, for every artifact** (Yulong, 2026-09-01 — this reversed the earlier inputs-only rule). The committed HTML is what the review round-trip runs on: the published page is where Yulong comments and suggests edits, the session applies them to the source, rebuilds, and republishes — and source, HTML and published page must stay one thing. Rebuild and republish update the committed HTML **in the same commit as the source change**, so the repo copy always matches what is live. `build/` remains gitignored scratch for intermediates that a build script regenerates.

An input that is itself ephemeral — a scan of the live environment, a query result, an API response — cannot be regenerated later because the thing it measured has moved on. Snapshot that alongside the source and say in `meta.yml` when it was taken.

`meta.yml` carries what the gallery cannot: the **publishing org**, which is unrecoverable afterwards and is exactly what breaks when accounts change, and the **author_model** that wrote the prose. Opus 4.8, Opus 5 and Fable do not write these pages (Yulong, 2026-09-08); the writer comes from `writer-priority` in `config/model-router.toml`, and `block_claude_authored_artifact.sh` refuses a publish whose `meta.yml` has no `author_model` or names a banned model. `author_model: generated` marks a page a script emits from structured data. The procedure is the `write-prose` skill.

## `meta.yml` is the row, so two publishes never conflict

The table in `ARTIFACTS.md` is generated by `scripts/build_artifacts_index.py` from these files — one row per file, spliced between the two markers in that file. Everything outside the markers is hand-written prose the builder never touches. The markers are link reference definitions (`[//]: # (...)`) rather than HTML comments, because `md2artifact` escapes raw HTML and an HTML comment would show up as literal text on the published page.

Before this, every artifact PR inserted a row at the top of the same table, so any two of them conflicted on the same line. Now they write two different files. A conflict inside the generated block is still possible when two branches both rebuilt it, and it is resolved mechanically: take either side, run the builder, commit. No row can be lost that way, because the rows are not in the file that conflicted.

Four keys exist for the row and nothing else — `summary` (the clause after the em dash), `public`, `status_note` (the clause after the status), and `index_source` when the Source cell is not just this directory. `artifacts/index-rows/README.md` documents all of them. The builder rejects a status outside the five-value vocabulary, a `superseded` row with no link to its replacement, a duplicate URL, a missing summary, and a raw `|` that would split the row; `tests/test_build_artifacts_index.py` pins each refusal.

An artifact whose `url` is one of the two placeholders (`unpublished`, `pending-first-publish`) or empty gets no row and is listed by the builder as a reminder. Any other value that is not a `https://claude.ai/code/artifact/<uuid>` address is a typo, not a placeholder: the builder names the file and the value and exits 2 under both the rewrite and `--check`, because silently skipping it would delete the repo's only record of a published page. Rebuild the index after editing any `meta.yml`, or CI fails on the drift.

That refusal is one case of the rule the builder now applies to every value it reads: **a placeholder is a value the schema names, never a value that merely happens to be falsey.** `false`, `0`, `''`, `[]` and `{}` are all equally falsey in Python, so a builder that normalises before it type-checks cannot tell any of them from "this key is absent" — and here "absent" meant a published page's row vanished from the table with a success exit code. Every key is now type-checked first, and a wrong type fails the build naming the file, the key, the type and the value as written; only then is a documented default applied. This bit twice through `url: no`, which YAML 1.1 reads as the boolean `False`, so quote any value that looks like `no`, `off`, `yes` or `on`.

The same rule covers files, because a row the builder cannot see is a row it drops just as quietly. Discovery reads `artifacts/<slug>/meta.yml` and `artifacts/index-rows/<slug>.yml`, and **every directory under `artifacts/` must have a row file in one of those two places** — one that does not is named and fails the build, under both the rewrite and `--check`. A row renamed `meta.yaml`, `metadata.txt` or anything else, or moved out of the directory, therefore shows up as what it is: an artifact with no row. Asked the other way round — "was this stray file meant to be a row?" — the question has no answer a filename can give, and two detectors that tried to guess it were defeated in review, so the builder no longer guesses. A page's own input data and its gitignored `build/` scratch are simply not rows, and nothing inspects them.

The gap this leaves is the row with no artifact directory at all: a file meant for `index-rows/<slug>.yml` and left somewhere else has no artifact to be missing from, so nothing catches it — `artifacts/index-rows/README.md` records that limitation, and nothing published from now on should need a file there. A key written twice in one row file is rejected as well: YAML keeps the last value and discards the first without a word, so two `url:` lines would index one address and silently forget the other, which is the same "a value is lost before anything checks it" harm one layer lower.

Name the source for what it is (`spec.md`, `plan.md`) — `md2artifact` qualifies a generic stem with the artifact directory, so the comment key is `review-<slug>-spec` rather than the `review-spec` that every spec in the gallery would otherwise share. All artifacts are read from one origin, so a shared key means two pages showing each other's comments; `tests/test_md2artifact_key.py` pins it. A specific stem keeps its historic key, so no already-published page is orphaned.

## The rule

Never pass a path under `tmp/`, `$TMPDIR`, `/tmp`, or any gitignored directory to the Artifact tool. Publish the committed HTML at `artifacts/<slug>/<slug>.html` — publishing is the last step, not the record, and the commit comes first.

For a repo whose artifacts are personal rather than about the code, the same layout goes in the private `dotfiles-personal` repo instead. This repo is public; personal working artifacts never land on a branch here.

## Worked example

`editable-review-layer/` is the first one built under the commit-the-HTML rule: `spec.md` is the source, `spec.html` the committed page, and both move together in every commit. `context-ledger/` predates the rule — its 1.5 MB page was judged too large to commit at the time, so only its pipeline plus the non-regenerable environment scan are stored; treat it as the grandfathered exception, not the pattern. If a future page is ever genuinely too large, that carve-out is Yulong's call, noted in its `meta.yml`.
