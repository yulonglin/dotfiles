# Experiments

**Run the small thing instead of writing about it.** A number that doesn't fit the story, "is X or Y better?", a mechanism claim asserted twice and tested zero times — each is an arm, not an opinion. Say the prediction before the run, in the manifest rather than in chat: a result that could not have come out the other way was not an experiment. One contrast, matched on everything else, an arm that can lose, reported whichever way it came out.

**Pilot before scale.** Nothing larger than about three samples until one or two samples have gone end-to-end through every stage — parse, audit, render, compute, measure, report — and been eyeballed this session on this code. This is a hard gate; n=1 does not validate scaling, since memory and length failures first appear around n≥4. Audit the input for truncation, chrome and placeholder tokens, with counts, before any stage consumes it. Freeze rendering rules, prompt hashes and thresholds in a manifest before the first scored call, and give every spending stage a `--dry-run` you read first.

**Fail within five minutes, not at hour three.** Check endpoint health, disk for 3× the projected output, memory against the readers' budgets, and auth before generating. Estimate dollars, GPU-hours, peak RSS and tokens out loud, and treat concurrency as a decision about what else shares the box. Debug on one-sample runs or fixtures, never by relaunching the full run with a print added. Validate outputs as they land; prefer append-only resumable pipelines whose resume keys include prompt and config hashes, so a reworded prompt invalidates stale rows rather than reusing them.

**Spend gate.** Estimate from actual rates. Under $100, run now and report the estimate with the result; $100 or more, propose and wait. Pre-paid cluster allocations skip it.

**The runner follows the resource profile, not habit.** Memory-heavy or long-lived work (past ~2 GB RSS or ~1 h) goes to pueue via `jexp`, whose cgroup caps are what stop the box OOMing. Pure API fan-out runs via Bash `run_in_background` from main context, where the queue would only add latency. Never launch detached work inside a subagent. Check a group's parallelism before submitting a fan-out. Commands, caps and sandbox failure modes: the `jobs` skill.

**Say whether it was exploratory or confirmatory.** Sweeping variants is fine and often the point, but the winner is a hypothesis needing fresh episodes before it is quoted as a result. Keep pinned revisions, seeds, prompt hashes and rendered inputs — but delete guard machinery that has caused more failures than it caught. The output directory should explain the experiment on its own to a capable but new colleague.
